5. Session 同步与跨会话广播

graph TD subgraph Disk["磁盘"] C1["~/.claude/projects/**/*.jsonl"] C2["~/.codex/sessions/**/*.jsonl"] end Watch["sessions-watcher
chokidar depth:6 polling 6s"] SyncA["ClaudeSessionSynchronizer"] SyncB["CodexSessionSynchronizer"] DB[("sessions 表")] Broad["chatRunRegistry.broadcastCanonicalSessionUpsert"] Status["chatRunRegistry.broadcastSessionStatus"] Clients["所有 connectedClients"] C1 --> Watch --> SyncA --> DB C2 --> Watch --> SyncB --> DB DB --> Broad -->|session_upserted| Clients Run["某 run 启动/结束"] --> Status -->|session_status| Clients

session_upserted侧边栏增量：session 同步器发现文件变更 / provider 公布原生 sessionId 时广播。

session_status跨会话生命周期：run 启动(running) + 结束(completed/failed/aborted) 时向所有客户端广播，让 A 会话能看到 B 会话的运行状态。

notification同会话内通知：Claude 的 Stop/SessionEnd/Notification hook 或工具审批，经 notification-orchestrator 只发给当前 run 的 writer。

8. 构建边界（拆仓关键）

前端 根 tsconfig.json（target ES2020, module ESNext, noEmit）+ vite.config.js，@/*→src/*，产物 dist/。

后端 server/tsconfig.json（target ES2022, module NodeNext, outDir dist-server）+ tsc-alias，@/*→server/*，产物 dist-server/。

共用 仅 shared/networkHosts.js（纯 JS 运行时函数）被两边 tsconfig include 且都直接 import。server/shared/（types/utils/interfaces）仅后端使用；前端在 src/stores/useSessionStore.ts 里独立镜像了 NormalizedMessage/MessageKind，无编译期约束。

⚠ 拆仓注意：LLMProvider 后端是 'claude'|'codex'，前端是 'claude'|'cursor'|'codex'|'opencode'，不一致；NormalizedMessage 两份定义需统一为一个 shared 包或显式对齐。详见 接口契约 §shared。

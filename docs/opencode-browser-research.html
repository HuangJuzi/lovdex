1 执行摘要

🎯 一句话结论
opencode 本身没有内置浏览器调试工具（内置 13 个工具中只有 webfetch / websearch 两个文本级 web 工具）， 但它原生支持 MCP 与插件机制，通过接入 Playwright MCP 或第三方浏览器插件（如 opencode-browser-plugin、@opencode-ai/browser-control、opencode-chromium）， 可以完整实现「打开 URL / 执行 JS / 截图 / 读 console / 网络请求 / 操作 DOM / 端到端调试」。
  • 定位：100% 开源（MIT）、provider-agnostic 的终端 AI 编码代理，由 SST 团队发布（仓库现迁移至 anomalyco/opencode，npm 包 opencode-ai），官方定位为 Claude Code 的厂商中立替代品。
  • 内置能力：bash / edit / write / read / grep / glob / lsp / apply_patch / skill / todowrite / webfetch / websearch / question。没有任何浏览器自动化工具。
  • 浏览器调试的正确姿势：在 opencode.json 配置 MCP server 或插件，把 Playwright/CDP 驱动的浏览器能力「挂」给 LLM。
  • 本报告结论置信度：核心结论经 25 条可证伪 claim 的 3 票对抗验证，23 条存活（2 条被杀），且用官方文档一手复核。

2 opencode 是什么

2.1 定位

官方文档原文：「A 100% open-source, provider-agnostic AI coding agent specifically built for terminal users.」（100% 开源、与厂商无关、专为终端用户打造的 AI 编码代理）。MIT 协议，GitHub 约 196k stars。

  • 官方将其与 Claude Code 对比：「very similar to Claude Code in terms of capability but with fundamental architectural differences」——能力相似，但架构根本不同（开源 vs 闭源、provider 无关 vs 绑定 Anthropic、内置 LSP、server/client 结构）。
  • 本地部署证据：本机 claudecodeui 封装以 opencode run --format json --dir <workspace> 无头调用（对照 v1.17.13），属于无浏览器能力的纯 agent 调用。

2.2 技术架构

  • Server / Client 分离：Server 跑在本机（处理 AI 调用、文件操作、状态持久化）；客户端（TUI / CLI / 桌面 App）连接 Server。
  • 内置工具集（13 个）：bash、edit、write、read、grep、glob、lsp（实验性）、apply_patch、skill、todowrite、webfetch、websearch、question。
  • 扩展机制三件套：① MCP server（local 子进程 + remote HTTP，见 §3）；② 插件 / Agent（markdown-frontmatter 声明）；③ 自定义工具（config 中定义的函数）。
  • 配置：项目级 .opencode/opencode.json 或用户级 ~/.opencode/opencode.json，MCP 配置与 Claude Code 的 mcp.servers schema 兼容。
  • 会话/状态：会话存 SQLite（opencode.db），token 用量、session 元数据可被外部系统读取（本机 claudecodeui 即如此集成）。

3 浏览器能力的来源：内置 vs 插件 vs MCP

3.1 内置工具：没有浏览器能力 ✅ 已证实

官方 tools 文档列出的 13 个内置工具中，没有任何浏览器自动化 / 截图 / DOM / console / 页面内 JS 执行工具。唯一的 web 相关工具是文本级的：

  • webfetch —— 「Fetch web content」：抓取并读取网页文本（HTTP 文本检索，不渲染页面）。
  • websearch —— 基于 Exa AI 的网页搜索（发现/检索）。
官方对二者的定位是「发现/检索」（discovery/retrieval），不是浏览器驱动。GitHub Issue #27543 仍在请求内置浏览器工具，对比对象明确写了「Claude Code has browser tool」——说明截至 2026 年中，官方内置浏览器工具仍不存在。

3.2 原生 MCP 支持：接入浏览器能力的主通道 ✅ 已证实

官方 MCP servers 文档明确支持本地与远程两类 server：

  • local：子进程方式（如 npx 启动），"type": "local" + "command": [...]。
  • remote：HTTP endpoint，"type": "remote" + "url"，自动处理 OAuth。
  • 「Once added, MCP tools are automatically available to the LLM alongside built-in tools」——接入的 MCP 工具与内置工具并列可用。

因此 Playwright MCP（playwright.dev/mcp）、基于 CDP 的浏览器 MCP server 都能直接挂进 opencode。

3.3 第三方插件/工具：生态补齐 ✅ 已证实

opencode-browser-plugin npm · Playwright 驱动

提供 browser_start / browser_snapshot / browser_click / browser_type，以及一个多动作的 browser 工具（open / navigate / screenshot / click / type / evaluate / wait / close）。支持 headless/headed、ARIA-ref 元素定位、多标签、持久 profile。

配置："plugin": ["opencode-browser-plugin"]

@opencode-ai/browser-control npm · 官方 org · 扩展+relay

「Local browser driver for trusted agents」：通过浏览器扩展 + 本地 relay，驱动用户已有的 Chromium 系浏览器（Chrome/Edge）。架构：Agent or CLI → local relay → browser extension → your browser。

opencode-chromium npm · quindart-com · 面向 v2 + MCP

Provider 中立的 Chromium 自动化，适配 OpenCode V2、MCP clients、Codex。提供 browser_run / browser_observe / browser_session / browser_finalize，截图、带 source map 的 console 堆栈、网络请求 drill-down、性能诊断（LCP/CLS/TBT）。

opencode-playwright-interactive github · mdc-git · 持久交互 QA

通过原生 custom-tool 系统提供持久化浏览器会话：ensureWebBrowser() 返回 session controller，含 resolveVisible / interactiveElements / click / doubleClick / hover / wheel / scroll / eval 等显式页面方法，可对真实页面做 e2e 调试。

另有 opencode-browser（michaljach）、bwb-browser、mare-browser-mcp 等社区包，以及 Steffen025 的 debug-first Browser Skill（默认采集 console/network/errors）。

4 能否「直接调用浏览器做调试」？——能力矩阵

结论：单独用 opencode 本体 = 不支持；组合 Playwright MCP 或第三方插件 = 全部支持。逐项对照：

调试动作opencode 内置+ Playwright MCP（官方能力）+ 第三方插件
打开 / 导航 URL✗✓ browser_navigate✓ open / navigate
执行页面 JS✗✓ browser_evaluate / browser_run_code✓ evaluate / run
截图（页面/元素/整页）✗✓ browser_take_screenshot✓ png/jpeg/webp、full-page
读取 console 输出✗✓ browser_console_messages✓ 部分插件 / Skill 默认采集
读取网络请求✗✓ browser_network_requests✓ chromium drill-down、4xx/5xx 统计
操作 DOM（click/type/fill/hover）✗✓ click / hover / drag / type / fill_form✓ click / type / interact
持久浏览器会话 / 多标签✗✓ tabs / session✓ 持久 profile
端到端调试真实页面✗✓✓
已知边界：opencode 插件侧「managed console/network 捕获 API」并非一等公民——如 opencode-playwright-interactive 依赖 Playwright 常规的 Runtime.enable 事件，不提供独立封装的捕获 API；需要强 console/network 精确捕获时，Playwright MCP 的 browser_console_messages / browser_network_requests 更完整。

工具内置浏览器调试MCP / 插件路径备注

Claude Code 内置 WebFetch/WebSearch；具备浏览器能力（社区与官方均提及 browser 能力） ✓ MCP 生态最成熟（6000+ apps），官方文档推荐 Playwright MCP 闭源、绑定 Anthropic 生态；浏览器交互多走 MCP/computer use
OpenAI Codex CLI CLI 本体无浏览器自动化；云端沙箱隔离 ✓ 支持 MCP（.codex/config.toml），但生态较受限 沙箱异步执行、PR 工作流；外部服务集成面较窄

横向结论：opencode、Codex、Aider 都没有「开箱即用」的浏览器调试；Claude Code 有内置 web 能力且浏览器工具最接近开箱即用，但严格的全功能 e2e 浏览器自动化在这四者中都要靠 MCP（Playwright 系）。opencode 的优势是开源 + provider 无关 + 插件生态，浏览器能力可以自由组合。

7 结论与配置建议

6.1 结论

  1. opencode 不能「直接」调用浏览器：内置工具集（13 个）里没有任何浏览器/截图/console/DOM/JS 执行工具；web 相关仅有文本级的 webfetch 与 websearch。
  2. 通过 MCP 或插件可以完整获得浏览器调试能力，且 opencode 把它们当作一等公民（MCP 工具与内置工具并列可用）。
  3. 推荐路径：需要严谨 e2e 调试 → Playwright MCP；需要驱动用户真实浏览器 → @opencode-ai/browser-control；需要轻量交互插件 → opencode-browser-plugin。

6.2 配置示例 A：Playwright MCP（推荐，能力最全）

// opencode.json（项目根目录或 ~/.opencode/opencode.json）
{
  "mcp": {
    "playwright": {
      "type": "local",
      "command": ["npx", "-y", "@playwright/mcp@latest"],
      "enabled": true
    }
  }
}

接入后 LLM 即可调用 browser_navigate / browser_evaluate / browser_take_screenshot / browser_console_messages / browser_network_requests / browser_click / browser_type 等做端到端调试。

6.3 配置示例 B：第三方浏览器插件

// opencode.json
{
  "plugin": ["opencode-browser-plugin"],
  // 或：
  // "plugin": ["@opencode-ai/browser-control"]   // 驱动你已打开的 Chrome/Edge
}

6.4 使用建议

  • Debug-first 工作流：选能「默认采集 console + network + errors」的插件（如 Steffen025 的 Browser Skill / opencode-chromium），而不是每次手动打开抓取。
  • 注意上下文占用：官方提醒 MCP server 会占用上下文，按需启用、可用 tools 配置按 server 前缀精确开关。
  • 真实浏览器 vs 无头：要复现用户真实环境（已登录态、扩展、本地 localhost 服务）用 browser-control（驱动现有浏览器）；要可重复的 CI 式调试用 Playwright 无头。
  • 版本提示：opencode 迭代快（本机封装对照 v1.17.13，已有 v2 与 Desktop 分支）；内置工具清单以 opencode.ai/docs/tools/ 为准，配置前查一下当前版本文档。

✓ 快速回复怎么工作

  • 点「常用语」chip = 填入输入框，不是直接发 —— 和会话页现有行为一致，你可以改完再发
  • 输入框回车发送，走 chat.send，任务页可以直接回复，不用跳会话
  • 回复完 sub_status 自动回落，面板就地刷新

  • 「常用语」要不要管全局列表（增删改）？还是只读复用会话页那一份？
  • 回复区是常驻，还是只在该任务「等待回答/审批」时才出现？
  • 要不要一并显示该会话最近几条对话（滚动小窗）？

⚠ 两个真实限制

  • 会话正在跑时后端会拒 RUN_IN_PROGRESS（无队列），此时输入框要置灰并说明原因
  • 会话被清理（无 session_id）时不能回复，只能重开

✓ 为什么能就地答

  • permission_request 帧本身就带 requestId + toolName + 完整 input（选项文案、计划全文、命令内容），不依赖会话 transcript
  • 答复帧 chat.permission-response 只需 { requestId, allow, updatedInput } —— 面板和会话页发的是同一个帧
  • 组件可整体复用：AskUserQuestionPanel / PlanDisplay 底部按钮 / Confirmation，只是换个挂载点

? 要请你在方案里定的

  • 唯一要改的地方：现在前端只在「当前打开的会话」收 pending 请求（sid === activeViewSessionId）。面板要按任务维度收，得放开这个作用域
  • 同时来多个待办时：面板里堆叠显示（前端本来就是数组），还是只显示最新一个？
  • 要不要保留「去处理 →」作为兜底入口（比如面板没渲染出来时）？

⚠ 几个真实的坑

  • AskUserQuestion / ExitPlanMode 永不超时（timeoutMs: 0，claude-sdk.js:152），会一直等；普通工具 60 秒后自动拒绝（toolApprovalTimeoutMs）—— 面板必须把倒计时显示出来，否则你回来发现被自动拒了
  • auto / bypassPermissions 模式下 SDK 直接跳过 canUseTool，这些提示根本不出现（claude-sdk.js:860）
  • 无人值守任务按策略直接拒掉交互工具，不会产生提示（auto-approve-policy.ts:252）

边界状态 四个真实会遇到的情形

这些不是异常，是日常：执行中发不出消息、审批超时被自动拒、auto 模式下根本没有待办、会话被清理后只剩重开。

① 执行中 · 消息进待发队列
② 多个待办 · 串行队列，会超时的排前面
③ 已超时自动拒绝 · 不静默消失
④ 无待办 / 会话被清理 · 待办区整个不渲染

决策表 已定，附理由

维度决定理由 / 约束
面板形态右侧 428px 停靠栏；窄屏降级为底部 sheet与仓库既有 ScheduledTasksPanel（420px 右栏 + sheet）同一套模式。列表只是变窄、不被遮罩，可以连着点下一行换内容。
电脑端默认视图表格（看板可主动打开）看板四列在宽屏上横向拉得过开，一屏能看的任务反而少。看板不删，改为需要时打开并持久化。
手机端视图看板（不给表格）与现状一致 —— 本来就是 isMobile ? 'board' : viewMode，这次只是把桌面默认值翻成 table。
关闭面板右栏整个收起，列表回到全宽✕ 与工具栏「隐藏面板」等效。收起态下点任意一行会自动重新展开 —— 不需要先找开关。「关闭」不等于「取消选中」：重新展开时回到刚才那一条。
进入详情面板底部「任务详情 →」才跳全页把原来的「点卡片 = 跳页」改成「点卡片 = 展开面板」，跳转变成显式动作。
快速回复点「常用语」= 填入输入框，不自动发送与会话页既有行为一致（handleInsertQuickReply 刻意不自动发送），所以是同一份全局常用语，不新造一套。
发送通道沿用 chat.send / buildTaskChatSend任务页已经在用这条通道（开始执行 / 重试），无需新接口。
多个待办串行队列，一次显示一个一个任务一个会话；后端 canUseTool 本就 await 完这个才走下一个。数据层仍按数组存，真并发也不丢。
排序会超时的排前面普通工具 60 秒后自动拒绝（会自己死掉，必须先救）；AskUserQuestion / ExitPlanMode 是 timeoutMs: 0 永远等。
倒计时只在会超时的条目上显示，<15 秒变红脉动显示真信息，防静默自动拒；对「永远等」的条目显示倒计时是假紧迫感。
答完反馈乐观移除 + 自动前进到下一个现有实现已是乐观移除。答失败或被 permission_cancelled 时标灰说明原因，不静默消失。
兜底入口底部小链接「在会话里处理 →」从现在的唯一按钮降级。防的是时序、断线重连、客户端版本不一致时你无路可走。
「总是允许」标注「仅本次会话有效」写进的是会话级 sdkOptions.allowedTools（claude-sdk.js:955），不是全局设置 —— 不标容易被误解。
无待办时待办区条件渲染，整个不出现auto / bypassPermissions 下 SDK 跳过 canUseTool；无人值守任务按策略直接拒交互工具。不能假设「一定有东西要答」。
消息队列执行中的输入进前端待发队列后端 RUN_IN_PROGRESS 无服务端队列，排队靠已有的 queuedDraft 机制，不在这次改动范围内重造。

改动范围 只改一处作用域

✓ 复用，不新造

  • 待办组件：AskUserQuestionPanel / PlanDisplay 底部按钮 / Confirmation 直接换挂载点
  • 协议：permission_request 进、chat.permission-response 出，帧格式不变
  • 发送：chat.send + buildTaskChatSend，任务页已在用
  • 常用语：复用全局 quick_replies 与会话页同一份列表

◆ 需要改的

  • pending 请求的接收作用域：现在只在「当前打开的会话」收（sid === activeViewSessionId），要放开到「当前展开的任务」——这是唯一的结构性改动
  • 桌面默认视图：taskViewMode 默认值 'board' → 'table'，并调整视图切换器
  • 面板容器：新增右栏/sheet 承载，参考 ScheduledTasksPanel
  • 列表点击语义：TaskCard / TaskRow 的 navigate() 改为展开面板

⚠ 三个必须写进实现的约束

  • 超时方向搞反就是灾难：超时是自动拒绝，不是自动通过 —— 倒计时必须显眼
  • 执行中不能发：RUN_IN_PROGRESS 无服务端队列，输入要进待发队列并明示「等这轮结束」
  • 无 session_id 时：待办区与回复区都不渲染，只留「重新执行」

确认后我把以上结论落成 spec 写入 docs/superpowers/specs/，再出实现计划。

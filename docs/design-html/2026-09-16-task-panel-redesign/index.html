Lovdex 任务面板重设计 · 3 个信息架构方案

这 3 份稿子回答同一个问题：任务面板该怎么组织，才让人一眼看出「现在什么在跑、什么卡住了、我该动什么」。 每份稿子都是全量的完整方案 —— 含主视图、详情页、以及各自遵循「移动端隐藏策略」的手机端； 用同一份拟真数据、同一套 Lovdex 现有配色令牌，所以差异只来自信息架构本身。

→

方案 1 与 2 治的是真问题。方案 1 治「9 列平铺、每列同权、行比信息重」；方案 2 治「等你批准 / 执行失败 / 待你验收 / 已逾期」这些行动信号没有聚合。方案 3 是换口味：降低编辑成本。

三稿共享一套修法：去厚重阴影、留白分行、行动信号前置、行内展开替代跳页。配色与字体保持 Lovdex 现状不动。

现状 · 结构
表格 9 列平铺、每列同权，窄屏必横向滚动；创建时间、最近活动这类低价值列与标题同权。
现状 · 信号
「等你批准 / 执行失败 / 待你验收 / 已逾期」全是派生信号，却散在子状态列与看板卡片内部，没有一处聚合。
现状 · 重量
每行独立卡片厚重阴影 + 悬停位移，行本身比行里的信息还重；双层筛选栏常年占掉一整行。

3 个方案

缩略图是结构示意；点开才是完整稿（每份含主视图 + 详情页 + 手机端三屏）。

1
精修数据表Refined Grid
推荐
组织方式
仍是表格，但 9 列收敛到 6 列：标题+标签+引擎合成一个单元，子状态并进状态列，创建/最近活动降为悬停浮现。
关键动作
点行就地展开详情抽屉，不再跳页；筛选压进一行工具栏；分组行亮出行动信号。
优化于
大数据量扫读；状态分组；批量操作。
代价
本质仍是表格，观感上限有限；悬停才显的信息在触控下不可达（移动端已降级为看板）。
打开完整稿 →迁移成本最低
2
行动收件箱Inbox & Triage
推荐
组织方式
顶部「需要你处理」聚合区（等你批准 / 执行失败 / 待你验收 / 已逾期），下方才是任务流。
关键动作
聚合条上直接给动作按钮（批准 / 重试 / 验收），不必先点进任务；详情卡顶部解释「它为什么出现在收件箱」。
优化于
响应速度；「有没有事等着我」这个最高频的问题。
代价
弱化台账属性，不适合「翻三个月前的记录」；聚合区为空时页面显得空。
打开完整稿 →信息重心最先到位
3
双栏主从Master–Detail
组织方式
左侧行式列表（非表格），右侧常驻详情面板；详情不再是独立页面。
关键动作
属性在右栏永远可直接编辑，不用点「编辑」再保存；窄窗时右栏降级为覆盖式抽屉。
优化于
高频改状态/优先级/项目；免去来回跳页。
代价
右栏常驻挤压列表宽度；不适合需要横向比较多列字段的场景。
打开完整稿 →编辑成本最低

3 份稿子共享什么

只有信息架构不同，其余全部锁死，避免「因为配色好看而选错架构」。

设计令牌（Lovdex 现状）

  • 主色 #3b82f6，暖米底 #f6f4ed，字体 Encode Sans
  • 状态 / 子状态 / 优先级 / Label / 执行引擎五张配色表取自 taskStatus.ts
  • 去厚重阴影，留白分行，圆角 12/16px

应用外壳

  • 顶栏：返回主页 + 分段切换（看板/表格/定时）+ 新建任务
  • 移动端隐藏策略：强制看板、表格按钮与文字标签隐藏只留图标
  • 桌面与手机 frame 三稿完全一致

拟真数据

  • 12 条任务，覆盖 5 状态 / 10 种子状态 / 4 优先级 / 7 Label / 4 执行引擎
  • 本地与远程项目、助手任务、定时任务、上下文来源
  • 逾期 · 今天 · 未来 · 无截止四种截止态

未动的部分

  • 功能不删：字段、筛选、批量选择、行内执行、上下文入口全部有位置
  • 纯静态 HTML/CSS，无 JS、无外链、无字体依赖
  • 都是设计稿，未改动 web/src 任何代码

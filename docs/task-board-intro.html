它是什么
01

一眼看全局

五列看板：积压 → 待做 → 进行中 → 评审中 → 已完成。所有任务按状态排开，属于哪个项目、进展到哪一步，一眼可知。

02

不是一个普通清单

它不是一份要你手动维护的待办列表，而是计划层与执行层合一：每个"进行中"的任务背后都指着一个活会话，没有空转的任务。

你的完整流程
1

建任务一次性把背景说清楚

写下标题和描述，指定它属于哪个项目，选定执行引擎（Claude 或 Codex，创建时定好，之后不用再纠结）。新任务默认落在积压。

2

开工点一下，AI 自动进入状态

任务在待做时，点卡片上的 "开始" → 自动创建这个任务专用的对话会话、跳进会话页，并把任务标题+描述作为第一条消息发给 AI。不用重新解释一遍任务。

手动触发
3

自动推进从此进度不再由你拖

会话真正跑起来 → 任务自动进入进行中；会话正常结束（AI 交付结果）→ 任务自动进入评审中；会话跑挂了且没有别的会话替它重试 → 任务自动退回"待做"，不被卡死在半路。

引擎自动
4

评审与收尾唯一必须你亲手做的判断

打开任务详情，看一眼 AI 交付的结果，满意就点 "标记完成"。这是"评审中 → 已完成"。

手动确认
5

随时回到现场任务和会话永远在一起

任务在"进行中"或"评审中"时，点 "打开会话" 就能跳回那个干活的对话页面，接着聊、接着看。

设计思路

思路 1看板是计划的层，会话是执行的层，两层是一体的

lovdex 真正的"干活"发生在对话里，看板只是把对话的状态翻译成你习惯的任务视图。所以每个"进行中"的任务背后都指着一个活会话——没有空转的任务。

思路 2机器的进度机器管，人的判断人来做

启动、进行中、交付这三步由会话的真实状态自动驱动，不需要你记账；你唯一不能外包的是最终判断——结果到底算不算完成。

思路 3状态即真相，不是装饰

因为进度是从执行现场自动读出来的，看板上显示的东西永远等于真实发生的东西，不会出现"标着进行中其实早停了"的僵尸任务。

思路 4失败不静默

会话挂了，任务自动回到池子里，而不是永远停在"进行中"骗你自己。任务不会无人认领地悬着。

思路 5一个任务绑定一个引擎

引擎在创建任务时定死（Claude / Codex），一致、可预期——不会每次开工才临时决定用谁跑。
